# 発信ループ設計 — 「プロンプトを書くな、ループを書け」を本プロジェクトに翻訳

> 出典の問題提起：Boris Cherny（Claude Code）／Peter Steinberger（OpenClaw→OpenAI）が独立に
> 「もうエージェントにプロンプトを送っていない。プロンプトを出す**仕組み（ループ）**を設計している」と収束。
> 本書は、その「ループエンジニアリング」を**この理論プロジェクトの発信（note / YouTube）専用に翻訳**した設計図。
> **設計書であって実装ではない**。動く自動化（スキル／スクリプト／cron）は本書の各ループ定義を満たす形で**別GO**で作る。
>
> 規模＝**シングルエージェントループ**（1エージェントが1工程を自走）。
> 人間ゲート＝**既存ハードゲートは維持**（note公開・アイキャッチ・YouTubeアップ・最終GO）。それ以外を自動化。

---

## §0 認識論的注記（憲法・最優先・緩めない）

出典スレッドの最後の警句をこのプロジェクトの言葉に置く：

> 「同じループを2人が作っても結果は真逆になる。一方は**深く理解した上でレバレッジ**をかける。
> もう一方は**理解を避けるため**にループを使う。」

このプロジェクトの価値は §0（[CLAUDE.md](../CLAUDE.md) §3）＝**内的整合・非自明予測・前提の可視化**にある。
データ適合でも再生数でもない。だからループの目的は **「量産」ではなく「理解の上の発信を、運用軽く・壊れにくく・積み上げる」**。

**ループに渡してはいけないもの（理解の核＝人間が握る）**：
- §0 の身分（「実測モデルでない・仮説生成ツール」）を緩める判断。
- 二層表記（Layer1＝式で語る／Layer2＝「比喩」と明示）の境界設計。
- 新しい「一致」（第Nの一致）の**正当性そのものの判断**＝機構と本当に一致しているか。

ループに渡してよいもの＝**型が決まった反復**（台本の章割り、TTS、字幕同期、note段落流し込み、トンマナ適用、QAチェック）。
**Go を押すだけの人にならない**ための線引きがこの §0。VERIFY（§6）はこの線引きを機械可読にしたもの。

## 1. 何が変わるか（人間ループ → 設計ループ）

```
【現状＝人間がループ】
  あなた → 指示 → エージェント → 出力 → あなたが目視 → 修正指示 → また出力 → …
  ループしているのは人間。スケールしない（あなたの時間が上限）。

【転換後＝設計ループ】
  あなた → ゴールだけ決める（例：controllability を解説動画化）
            ↓
  ループ：DISCOVER → PLAN → EXECUTE → VERIFY → ITERATE（自走）
            ↓
  人間ゲート（公開・アイキャッチ・最終GO）でだけ止まる
```

人間の仕事が「毎回の確認」から「**ゴール設定＋ゲート承認＋ループ設計の改善**」に移る。

## 2. 共通骨格（全ループ共通の5フェーズ）

**クローズドループを採用**（オープンループ＝自由探索はトークン爆発。今すぐ回すならクローズド一択）。
クローズド＝**ゴール明確／ステップ定義済み／各ステップに評価（VERIFY）あり／終了条件あり**。

| フェーズ | 中身 | このプロジェクトでの具体 |
|---|---|---|
| **DISCOVER** | 入力を集める・現状把握 | 対象記事/テーマを読む、既存docs・既存作との重複チェック、素材（既存SVG・グラフ）の所在確認 |
| **PLAN** | 手順とアウトプット形を決める | 章割り（5章）、段落構成、流用する資産、終了条件を確定 |
| **EXECUTE** | 生成 | 台本・TTS・字幕・index.html・note段落流し込み 等 |
| **VERIFY** | 評価関数で自己採点（§6） | §0チェック＋整形QA＋トンマナ＋技術QA。**ここが品質の番人** |
| **ITERATE** | VERIFY失敗→DISCOVERに戻る／成功→終了条件へ | 失敗箇所だけ直して再VERIFY。N回失敗で人間に上げる（暴走防止） |

**終了条件（共通）**：VERIFY全項目green かつ 人間ゲート手前まで到達。
**暴走ガード**：同一フェーズで ITERATE 3回失敗 → 自動停止して人間にエスカレーション（[CLAUDE.md](../CLAUDE.md) 連打防止と同趣旨）。

## 4. 4つのループ定義

各ループ〔ゴール｜DISCOVER｜PLAN｜EXECUTE｜VERIFY｜終了条件｜人間ゲート｜使う部品〕。
**規模はすべてシングルエージェント**（1工程を1エージェントが自走）。L-Cだけ各サブを直列に並べる薄いオーケストレーション。

### L-A 記事生成ループ（テーマ → note下書き）

- **ゴール**：1テーマを `site/.../articles/<slug>.md` 相当の記事にし、note**下書き**まで載せる。
- **DISCOVER**：テーマの元ネタdoc（正本/比喩/橋渡し/応用）を読む。既存記事と重複チェック（同じ「一致」を二度書かない）。差別化照合（article-pipelineメモの照合先）。
- **PLAN**：表題フック（[note_表題フック規約.md](note_表題フック規約.md)）に沿う見出し設計。二層表記の配置（式は深掘りリンク／本文は比喩）。固定タグに `#動物行動学` を必ず含める（[note固定タグ規約メモ]）。
- **EXECUTE**：本文Markdown生成 → `astro2note.py` で `{title, blocks[]}` 変換 → chrome-devtools MCP で note下書き（タイトル＋段落＋h2／`note-publish` SKILL の Step1–9）。
- **VERIFY**：§6 共通チェック ＋ note整形QA（**h2＝マーカー全件・emptyH2:0・chars一致**／SKILL Step6）。引用・リスト・hrは自動付与しない（SKILL「やらないこと」）。
- **終了条件**：下書きURL（`editor.note.com/notes/<id>/edit/`）が出て VERIFY green。
- **🔴 人間ゲート**：**アイキャッチ手動（CDP不可）／会員ゲート設定／公開ボタンは人間**（BAN回避・SKILL Step10）。
- **部品**：note-publish SKILL＋chrome-devtools MCP＋Memory（差別化照合）。

### L-B 動画生成ループ（記事 → YouTube解説動画 完成mp4）

- **ゴール**：1記事を横型16:9・約3分・TTSナレ＋同期字幕の解説動画 mp4 にする（縦型ショートは別系統だが同骨格）。
- **DISCOVER**：`site/.../articles/<slug>.md` を読む。流用元の既存作（five-types/reward-trap/fear explainer）と資産表（HANDOFF §キャラ/グラフ）を確認。
- **PLAN**：台本5章構成（CH1フック→CH2-4論点3→CH5まとめ＋§0注＋CTA）。各章25–40秒・計約1000字。流用するSVG/グラフを決める。
- **EXECUTE**：narration/ch1-5.txt → `edge-tts`（ja-JP-Nanami・rate+10%）でmp3+srt → `ffprobe` 実測 → `make_groups.py` で字幕配列 → index.html（既存コピー＋差替）→ BGM（ffmpeg・volume0.22）→ `hyperframes render`。
- **VERIFY**：§6 共通 ＋ 技術QA（**lint 0 error・inspect 両方 0 issue・音量 mean -18〜-20dB**／HANDOFF）。トンマナ（色・Noto Sans JPのみ・字幕ゾーン下185px厳守）。§0末尾注記あり。
- **終了条件**：mp4 が出て VERIFY green。ソースのみ commit（mp4/mp3/srt/bgm/frames除外）。
- **🔴 人間ゲート**：**YouTubeアップロードは人間**（自動化しない）。概要欄4点（チャプター/記事リンク/note導線/§0注）。サムネ生成は半自動（thumbnail.html→screenshot）だが投稿は手動。**push前に gh account 切替**。
- **部品**：video-pipeline（HANDOFF）＋hyperframes CLI＋edge-tts＋ffmpeg＋Memory（video節）。

### L-C 全体オーケストレーション（1テーマ → 記事＋動画＋両投稿準備）

- **ゴール**：1テーマからL-AとL-Bを**直列**で回し、note下書き＋YouTube mp4 を両方そろえる。
- **構造**：薄いオーケストレーター（シングル）。`DISCOVER(共通：テーマdoc読む)` → `L-A` → `L-B（L-Aの記事を入力）` の順。L-Bは記事を入力にするので**L-A完了後**に走る（依存あり＝直列が正しい）。
- **VERIFY**：L-A・L-B各々のVERIFY ＋ **整合チェック**（記事の主張と動画台本の主張がズレていないか・同じ§0注記か・タイトル/フックの一貫性）。
- **終了条件**：note下書きURL＋mp4＋（任意で）両者のメタ（タグ・概要欄）下書きがそろう。
- **🔴 人間ゲート**：L-A・L-Bのゲートを**両方**通過要（アイキャッチ・note公開・YouTubeアップ・最終GO）。ここは束ねない。
- **注意**：フリート（並列艦隊）にはしない＝**依存が直列**（動画は記事を必要とする）。並列化してもトークンを食うだけで早くならない。

### L-D ネタ発掘 / リサーチループ（入口の供給）

- **ゴール**：次に書く価値のあるテーマ候補を、**機構と本当に一致するもの**だけ供給する（L-A/L-Cの入力源）。
- **DISCOVER**：既存「一致」（応用_集団蜂起/取り付け騒ぎ/動機の締め出し/子育て）と被らない領域を、社会行動学・経営現象から探索（Web調査はサブエージェント可）。
- **PLAN**：候補ごとに「どの定理/エンジン（恐怖/報酬/学習/集計）に対応するか」仮の写像を立てる。
- **EXECUTE**：候補リスト（テーマ・対応機構・非自明予測の核・既存docsとの差分）を出す。
- **VERIFY**：§0チェックを**最も厳しく**＝「比喩を式に薄めていないか」「本当に機構から導けるか・通俗経営論に後退していないか」。**ここはループに最終判断させない**（§0より：一致の正当性は人間が握る）。VERIFYは“疑わしいものを落とす”adversarialな採点に留め、採用は人間。
- **終了条件**：人間レビュー待ちの候補が N件たまる（採用＝人間ゲート）。
- **🔴 人間ゲート**：**新しい「一致」の採用判断は人間**（理論の核・誇張は理論を弱める）。
- **部品**：Explore/general-purpose サブエージェント＋WebSearch＋docs（正本/橋渡し）＋Memory（theory-docs節）。

## 5. 人間ゲート一覧（自動↔手動の境界線・既存ルール厳守）

ループは下表の手前で必ず止まる。**ここを自動化しない**ことが、既存ルールとの整合＝事故防止。

| ゲート | 場所 | なぜ手動か（出典ルール） |
|---|---|---|
| **note 公開ボタン** | L-A / L-C 末尾 | note の spam/bot検知でBANリスク（note-publish SKILL Step10） |
| **note アイキャッチ画像** | L-A | CDP不可・upload_file禁止（note-publishメモ）＝人間手動 |
| **note 会員ゲート設定** | L-A（メンバー限定記事） | メンバーシップ追加→試し読みライン（手順正本＝docs/note運用.md §8） |
| **YouTube アップロード** | L-B / L-C 末尾 | 自動化しない（HANDOFF §YouTube運用） |
| **新「一致」の採用** | L-D 末尾 | 理論の核・§0（誇張は理論を弱める）＝人間判断 |
| **最終 GO（公開可否）** | 全ループ | [CLAUDE.md](../CLAUDE.md)：破壊的/外向き操作は明示GASまで止まる |
| **git push 前の gh 切替** | L-B commit時 | global共有のgh account（HANDOFF）＝push前に明示切替 |

**自動でよい範囲**：DISCOVER〜EXECUTE〜VERIFY の生成と自己採点まで（下書き・mp4生成・QA）。
**手動で握る範囲**：上表（外向き発行・理論の核判断）。

## 6. VERIFY 評価関数（このプロジェクト固有の自己採点・ループの肝）

出典が言う「テストが自動検証する」の中身。**汎用の lint ではなく、このプロジェクトの品質を守る評価項目**。
各ループの VERIFY フェーズは下記を機械的にチェックし、**1つでも赤なら ITERATE に戻す**。

### 6-1. §0・ブランド核チェック（全ループ共通・最重要）
- [ ] **誇張禁止**：「実測で当たっている」と読める表現がない（仮説生成ツールである）。
- [ ] **二層表記**：Layer1は式で語る／Layer2は「比喩」「レンズ」と明示。比喩を式に薄めていない。
- [ ] **断定回避**：特定企業/単一原因を断定していない（末尾§0注記あり）。
- [ ] **ブランド核**：動物・生態系の比喩が、一般的マネジメントtipsに薄まっていない。
- [ ] **法令・数値**：労基法・最低賃金等を扱うなら出典＋「変わりうる」注記あり（[CLAUDE.md](../CLAUDE.md) §6）。

### 6-2. 整形・配信規約チェック
- [ ] **固定タグ**：note記事に `#動物行動学` を必ず含む（note固定タグ規約・2026-06-15〜）。
- [ ] **表題フック**：[note_表題フック規約.md](note_表題フック規約.md) に沿う。
- [ ] **（L-A）note整形QA**：h2＝見出しマーカー全件・**emptyH2:0**・fig:0・chars が Step5 と一致。
- [ ] **（L-B）技術QA**：`lint` 0 error・`inspect` 両方 0 issue・音量 mean **-18〜-20dB**・字幕はみ出しなし。
- [ ] **（L-B）トンマナ**：規定色・Noto Sans JPのみ（Serif/mono非対応）・下185px字幕ゾーン侵さない。

### 6-3. 再現性・整合チェック
- [ ] **（シム関連を含むなら）シード固定**（[CLAUDE.md](../CLAUDE.md) §6 再現性）。
- [ ] **（L-C）記事↔動画整合**：主張・§0注記・タイトル/フックが一貫。
- [ ] **重複なし**：既存記事/動画/「一致」と内容が被っていない。

> この評価関数が「理解を避けるための自動化」を防ぐ。VERIFYが通っても §0判断（新一致の採用等）は人間ゲート（§5）に残す。

## 7. トークンバーンという現実の壁（抑制方針）

- 出典：中規模タスクで数十万、フリートで数百万トークン規模になりうる。
- **本設計はシングル×クローズド**＝最も倹約的な構成を意図的に選択（フリートにしない）。
- 抑制策：
  - **DISCOVERで既存資産を最大流用**（L-Bは既存explainerをコピー＝ゼロから書かない）。
  - **VERIFY失敗は3回でエスカレーション**（無限ITERATE＝トークン暴走を断つ）。
  - **L-C を並列化しない**（依存が直列・並列はトークン増だけで速くならない）。
  - 重い探索（L-Dの広域Web調査）だけサブエージェントに切り出し、本線は単一文脈で軽く保つ。
- 将来、低価格・長コンテキストモデルが出れば L-D の探索深度を上げる余地（出典の指摘どおり）。

## 8. 最小の第一歩（運用軽く始める）

出典ToDo「まずクローズドループから」に従い、**いきなり全自動化しない**：

1. **手回しで型を1周**：次の1記事で L-A を**人間が各フェーズを手で実行**し、5フェーズ／VERIFY項目／ゲートが実態に合うか検証（本書を実地で叩く）。
2. **VERIFY を先にスクリプト化**：§6 のチェックを小さなスクリプト/チェックリストにする（評価関数が先・生成自動化は後）。理由＝評価が無いループは「Go押すだけ」に堕ちる。
3. **L-A の EXECUTE 接続を1本自動化**（note-publish SKILL は既に半自動＝ここを5フェーズに載せ直すだけ）。
4. うまく回ってから **L-B → L-C**。L-D は探索なので最後（誤った「一致」を量産しないため慎重に）。
5. 各ステップで Memory（`doubutsu-*.md`）に学びを追記＝ループ自体を ITERATE する。

> **実装は本書の各ループ定義（§4）と評価関数（§6）を満たす形で別GO**。本書はその受入条件。
