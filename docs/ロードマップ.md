# ロードマップ — 次にやること

> 二層理論（[正本](正本_ミクロ機構.md)／[比喩](比喩_5類型マクロ.md)／[橋渡し](橋渡し_対応表.md)）を、検証と発信へ接続する作業計画。
> 推奨順序：**まず単一エージェントのシム（理論側）で妥当性を挟んでから**、多エージェント化と発信に広げる。健全性が確かめられる順。

---

## A. 理論側ロードマップ（Layer1 起点）

### A-1. ストレステスト（最優先）★ここから
既知の経営現象を取り、モデルが正しく予測するか反証を試みる。**多エージェント化の前に妥当性を確かめる**ため、まず単一エージェントのシミュレーションで挟む。

- **定理B シム（最初の検証対象）**：統制可能な罰 vs 統制不能な罰で、Ĝ と行動率の時系列がどう分岐するか。連続でなく **不連続な regime change** が再現されるか。
- **定理A シム（次）**：ρ を超える報酬を与えてから撤回し、δ の符号反転と κ増幅、行動の崩れを確認。
- 既知現象との照合：成果給導入後の士気低下（定理C）、粛清後のリスク回避の伝播（定理D＋多エージェント）。

### A-2. 操作化
係数群（g, τ, κ, Ĝ, k, f, I₀, w）のうち、実在組織で観測・推定できるのはどれか。理論を測定に接続する。
[比喩 §3 診断②](比喩_5類型マクロ.md) の代理指標（ミス報告率＝恐怖指数、提案数＝学習指数 …）が、どのパラメータの観測代理になるかを対応づける。

### A-3. 多エージェント層（＝「同調」「文化」の形式化）★橋の完成
個々の π がどう集計され、規範・伝播・均衡になるか。ここで初めて「文化」を形式的に定義できる。
**これが完成すると、[橋渡し_対応表.md](橋渡し_対応表.md) の5類型を「対応表」から「導出」へ格上げできる**（各型＝集計系のアトラクタ／regime として導く）。Layer1 §8 と Layer2 §4-5（生態系・継ぎ目管理）が、ここで一つの式系に閉じる。

## B. シミュレーション実装計画（`sim/`・別GO）

§A-1 を実装に落とす。CLAUDE.md §7 の方針に従う。

- **言語**：Python（`numpy` 中心、可視化 `matplotlib`）。Windows 前提。
- **設計**：
  - `Agent`：V, τ, k, Ĝ を保持し softmax で行動選択、マスター方程式（[正本 §5](正本_ミクロ機構.md)）で更新。
  - `Environment`：随伴構造 C を定義し R を返す（統制可能／不能を切替可能に）。
  - `run_episode()`：時系列を回す。
- **パラメータ**：設定ファイル（`config.yaml` 等）で外出し。各係数の意味をコメントで明記。
- **再現性**：乱数シード固定。
- **明記義務**：各シムが「理論のどの主張を検証しているか」をコード・README に書く。
- **粒度**：定理ごとに小さくコミット（定理B → 定理A の順）。

## C. 発信側ロードマップ（Layer2 起点・`site/`・別GO）

### C-1. 最小サイト（MVP）
公開できる最小：ホーム ＋ 理論ページ ＋ 記事一覧 ＋ 記事1本 ＋ About。
- 技術：Astro 既定（着手前に確定）。Tailwind。記事＝MDX、1ファイル＝1記事。
- 理論ページの元ネタ＝[比喩_5類型マクロ.md](比喩_5類型マクロ.md)。正本（式）は「深掘り」リンク先に置き、二層表記を保つ。

### C-2. 記事の作り方（比喩を薄めない）
[橋渡し §7](橋渡し_対応表.md) の検証可能な4予測を、5類型の物語で運ぶ。
- 例：「報酬の撤回はなぜ据付より危険か」＝ 定理A を ハイエナ型の燃え尽きで語る。
- 法令・数値（労基法・最低賃金 等）を扱う記事は、出典＋「変わりうる」注記を必須（CLAUDE.md §6）。

### C-3. チャネル展開
サイト＝母艦（思想の正本）。YouTube／note／SNS は外部チャネル。1コア→全展開。再生数を主指標にしない（継続して出せること・思想がストックされることが成功指標）。

## D. 推奨実行順（全体）

1. **融合 docs 整備** … ✅ 本コミット群で完了（CLAUDE.md ＋ docs 4本）。
2. **定理B シム**（`sim/`）… 統制可能/不能で不連続 regime change を再現。**次の一手の最有力**。
